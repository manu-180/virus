### 5. Endpoints nuevos

#### `POST /api/ideas/test-seed`
Atajo "1-click test video": inserta una idea draft tomando un hook al azar de `viral_hooks_seed` (es-AR), opcionalmente la aprueba al toque y dispara `virus/idea.approved`.

Body:
```json
{ "projectId": "uuid (opcional)", "autoApprove": true }
```
Si `autoApprove=true`, devuelve `{ ideaId, videoId, hook }` con status 202. Si no, devuelve solo `{ ideaId }` y queda en draft para que el usuario apruebe a mano.

[apps/web/src/app/api/ideas/test-seed/route.ts](apps/web/src/app/api/ideas/test-seed/route.ts)

#### `POST /api/videos/[id]/retry`
Reintenta un video fallido **desde el último paso completado** (no rehace audio si ya está):
- Si tiene captions → re-emite `virus/captions.ready` (sólo render)
- Si tiene audio → re-emite `virus/audio.synthesized`
- Si tiene script → re-emite `virus/script.generated`
- Si solo tiene idea → re-emite `virus/idea.approved` (full pipeline)

[apps/web/src/app/api/videos/[id]/retry/route.ts](apps/web/src/app/api/videos/[id]/retry/route.ts)

## ⚠️ Cosas que todavía hay que hacer (no toqué)

### Worker: corre local. Hay que deployarlo a producción
El worker Inngest está corriendo local (`@virus/worker#dev`). Para que la app funcione cuando no estés con la PC encendida, hay dos caminos:

**Opción A — Vercel + Inngest Cloud (recomendado)**
1. Crear cuenta en [Inngest Cloud](https://inngest.com) (free tier alcanza para arrancar).
2. Conectar el endpoint del worker. La app web ya expone `/api/inngest` — al deployar a Vercel, Inngest Cloud lo descubre solo.
3. Variables de entorno en Vercel: copiá las `INNGEST_EVENT_KEY` y `INNGEST_SIGNING_KEY` del `.env.local`.
4. El worker como proceso separado **no haría falta** si ponés todas las funciones del worker en `/api/inngest` de la web (hoy están en `apps/worker`).

**Opción B — VPS / Fly.io**
Deployar `apps/worker` como long-running process. Inngest Cloud lo conecta vía signing key.

Mientras tanto: **mantener el worker local andando** (`pnpm dev` en la raíz del monorepo). Si lo cerrás, los videos quedan en `pending` para siempre.

## 🧪 Cómo probar todo

1. Asegurate de que el worker y el web dev server estén corriendo (deberían estar ya).
2. Visitá `http://localhost:3003/dashboard/ideas` — debería listar la idea existente "El error más común…".
3. Hacé click en **"Generar video de prueba"** arriba a la derecha.
4. Te redirige a `/dashboard/pipeline` y aparece un video nuevo en `pending` o `scripting`.
5. El status va cambiando en tiempo real (script → audio → captions → rendering → ready).
6. Si falla, vas a ver el error en rojo + botón **Reintentar**.

**Tiempo esperado para ver el resultado:** ~3-6 minutos (script ~30s, audio ~1m, captions ~30s, render Lambda ~1-3m).
